# 排错

先区分“配置已保存”“Klipper 已加载”“通信读回有效”“物理效果验证”。仅看到卡片或某个配置对象，不证明驱动已连接；缓存电流也不等于相电流测量。

| 现象 | 判断和处理 |
| --- | --- |
| 未知配置节 `driver_monitor` | 核对模块是否在正在运行的 Klipper `klippy/extras` 中、文件名是否正确；不要只检查另一个源码副本 |
| 找不到 LYX 驱动／没有 LYX 卡 | 核对已加载的 `[lyx9231 <stepper>]`、对象名称和 Klipper ready 状态；监测器不创建驱动 |
| 未知 `config_modbus_uart` 等 MCU 命令 | 主机 LYX 代码和 MCU 固件不匹配；安装监测 Python 文件不能给普通 MCU 固件补充命令 |
| LYX 初始化在某寄存器失败 | 正式驱动 connect 阶段写入／回读失败，先处理原生通信或配置；这发生在监测 ready 之前 |
| 原生读取成功，但卡片仍是旧结果 | 原生 `LYX_READ_REG` 不更新监测缓存；看字段采样时间，等待后台或用监测 REFRESH |
| `busy` 或正在采集 | 当前完整查询或总线被占用；不排队、不计通信失败，不要连续重复 POST |
| `invalid` | 没有可发布的有效值；不等于收到零字节，也不能把异常帧数字当报警 |
| `error` | 完整原生查询抛错或耗尽重试，查看简短异常类型及日志；当前驱动批次结束，其他驱动可继续 |
| 手动请求 HTTP 超时 | 结果未知，后台原生查询可能仍运行；先查询缓存和日志，不自动重发写入／读取命令 |
| 暂停按钮禁用／AUTO0 被拒绝 | 开启报警停机保护时属于预期行为；关网页不会关闭保护 |
| enabled=true 但 armed=false | 等待使能计划时刻生效，或已停机／未 ready；首次已使能使用队列末端作为保守门槛 |
| 改了 `microstep` 后配置错误 | 同时核对 stepper 的 `microsteps`，必须一致且符合 25600 换算范围；256 细分当前不支持 |
| 缓存 hold_current 有值但实际不像半流 | `driver_half_cur_en:0` 时半流关闭；缓存值不证明硬件进入保持电流 |
| 速度／误差数值很大 | 卡片当前显示无符号原始值，可能与原生 DUMP 的有符号格式不同，不应自行当 RPM 或角度 |
| 曲线缺段 | 读取失败、采样间断或会话切换会断线；不补零，不能用插值掩盖通信失败 |
| 日志仍持续出现收发内容 | 新增事件做了去重，但原生 LYX 底层逐帧日志未修改 |

## 配置重新加载与 Python 更新

单纯 Klipper `RESTART` 可能不重新导入已加载的 Python 模块。更新模块文件后，应按安装说明重新加载对应主机进程，再核对有效配置和模块版本。某些发行版的服务启动钩子会执行固件更新，不能不经检查把“主机重载”等同于“绝不刷写”；使用本机已核实的流程。

初始化失败时不应反复盲目重启、写寄存器或更改引脚。先保留失败寄存器与有效配置的最小证据，核对主机／MCU 版本、引脚、通信地址和模块所需接线。当前原生波特率固定为 38400；监测器没有波特率参数。

## 触发报警停机后

错误消息应含轴、中文原因、原始报警值和时间。先处理机械／接线／驱动问题；通信失败和报警值不能混为一类。保护用逻辑 EN，不能代替物理电气保护。

据既有使用者说明，驱动报警需要断电重新上电才清除；本项目未做断电清码试验。重新进入 Klipper ready 仅清本模块主机锁存，不证明芯片报警消失。模块不执行清码或自动恢复运动。真实故障测试尚未覆盖，不能仅凭离线测试声称已验证所有故障场景。

## 离线测试无法运行

在仓库根目录运行：

```sh
python3 -B backend/test_driver_monitor.py
```

仅需 Python 标准库与完整仓库内 `vendor/lyx` 三文件，不需要 Klipper 安装或设备。启动时校验三份源码的固定 SHA256；文件缺失或哈希不同会在测试开始前失败，不能通过跳过真实原生路径来声称全部回归通过。

若有意升级依赖，应先审查驱动协议、锁、读写和配置变化，再同步测试基线；不要仅为消除错误随意更新期望哈希。完整测试范围与尚未验证部分见[验证记录](VALIDATION.md)。
