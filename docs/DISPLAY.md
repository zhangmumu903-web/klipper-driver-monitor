# 驱动监测卡片：显示逻辑与使用说明

卡片用于查看 Klipper 后台提供的驱动状态。LYX9231 由后台定时查询并缓存，TMC 只展示 Klipper 已有缓存。网页关闭后，后台仍按自己的配置运行；打开更多网页不会建立更多 UART 采集循环。

安装步骤见 [INSTALLATION.md](INSTALLATION.md)，后端参数见 [CONFIGURATION.md](CONFIGURATION.md)，采集与停机判定细节见 [ARCHITECTURE.md](ARCHITECTURE.md)。本文中的主机名、`.example` 域名和 RFC 5737 文档地址均为虚构示例，不是可直接连接的设备。

## 1. 每个驱动一张卡片

页面自动展示当前快照中的全部驱动，不需要用下拉框切换。标题使用 Klipper 配置对象名，例如 `stepper_x`、`stepper_y`、`extruder`；挤出机驱动也独立展示。后端发现列表变化后，卡片随下一次成功快照新增或移除。

| 项目 | LYX9231 卡片 | TMC 卡片 |
| --- | --- | --- |
| 来源 | `driver_monitor.drivers` 与各轴读数缓存 | Moonraker 对象列表中的 `tmcXXXX <stepper>` 及其状态缓存 |
| 主要内容 | 报警码、转速原值、角度误差原值，两条近五分钟曲线 | Klipper 提供的电流设定、温度和驱动状态字段 |
| 主动采集 | Klipper 后台串行调用原生完整查询 | 本组件不调用 `DUMP_TMC`，不触发 TMC 现场读取 |
| 单卡按钮 | “立即刷新”，固定绑定该卡片的轴 | 无现场刷新按钮 |
| 报警停机保护 | 可显示本后端的每轴保护状态 | 不纳入本项目的 LYX 报警停机逻辑 |

例如 X 卡片的刷新只发送 `DRIVER_MONITOR_REFRESH STEPPER=stepper_x`，Y 卡片固定发送自己的轴名。某轴刷新报错显示在该卡片；连接问题和全局自动监测状态显示在顶部。界面不会在目标轴消失时把刷新转发给另一轴。

所有 LYX 卡片共用顶部一个“暂停全部 LYX 监测／恢复全部 LYX 监测”按钮。它改变同一后台的全局状态，其他客户端随后也会看到变化。参数调整保留在 CFG 配置中，卡片没有电流、细分或模式设置入口。

## 2. 网页刷新与后台采集是两件事

```text
已有 LYX 驱动 → Klipper 后台采集与统一缓存 → Moonraker → 各客户端页面
已有 TMC 状态 ────────────────────────────→ Moonraker → 各客户端页面
```

每个页面实例只有一个共享控制器，全部卡片共用快照。可见的仪表板在初次挂载时读取一次，然后在前一次定时回调结束约 3 秒后继续查询；请求耗时、页面忙碌或切到后台会影响实际间隔，并非严格每 3 秒完成一轮。

一次正常完成的快照包含三个只读 GET：

1. `/printer/info`：核对主机身份。
2. `/printer/objects/list`：发现监测与 TMC 对象。
3. `/printer/objects/query?...`：取回这些对象的缓存。前两项并发，第三项使用对象列表构造。

驱动数量增加不会让每张卡片各发一套请求。页面内每 500 毫秒的显示与主题更新也不产生网络查询。多个电脑、手机或平板各有自己的 GET 循环，但读取同一个后台缓存；客户端数量不会改变后台 UART 调度。

被动轮询不会自动 POST。只有用户明确点击刷新或全局按钮，且操作检查通过，才向同源 `/printer/gcode/script` 发送一次对应命令。手动操作前后还会读取快照，因此点击按钮时 GET 数量多于普通轮询。

切离仪表板、隐藏标签页或移除组件会暂停该页面查询；返回可见仪表板时再读取。关闭页面不会发送 `AUTO ENABLE=0`，也不会停止已开启的后台保护。后台采集频率由 `cycle_interval`、`read_gap` 等 CFG 参数决定，与网页的约 3 秒刷新间隔无关。顶部按后台实际字段展示调度，例如“报警→转速→角度误差 · 轮间隔 1 秒 · 项间隔 0.2 秒”；轮间隔从全部驱动本轮处理完毕后计算。

## 3. 如何理解数值与时间

| 显示项 | 含义与边界 |
| --- | --- |
| 报警码 | `ALARM_CODE` 有效寄存器原值；有效非零值以报警色提示。是否停机还取决于后台保护条件 |
| 转速原值 | `MOTOR_SPEED` 无符号寄存器值，没有在卡片中换算成 rpm 或 mm/s |
| 角度误差原值 | `ERROR_ANGLE` 无符号寄存器值，没有在卡片中换算成角度或位置误差 |
| 驱动信息中的型号、电流寄存器原值 | 后台静态项缓存；电流原值不是安培测量值，也不会因每次三项刷新而自动重读 |
| TMC 运行／保持电流设定 | Klipper 缓存提供的设定值，使用 A 显示；不是实际相电流测量 |
| TMC 温度／状态字段 | 只显示接口确实提供的字段。缺少报警字段不能解释为“没有报警” |

LYX 读数必须同时满足 `outcome=ok`、整数和 `0…65535` 范围，才显示“读取成功”。`0` 是有效读数。无记录显示“未读”；无效回复或读取错误显示“读取失败”和 `—`，不会把失败转换成零，也不会用上一次成功值冒充新结果。

每个寄存器旁的时间对应该项查询结束时间，不是整张卡片的网页刷新时间。后台 `ended` 和快照 `eventtime` 使用单调时钟；页面按下式估算本地墙钟时间，再按客户端时区显示：

```text
该项显示时间 ≈ 浏览器收到快照的时间 − (eventtime − ended)
```

这个估算会受网络延迟和客户端时钟影响，不能作为精确同步时钟。旧静态值保留自己的时间，跨日会显示日期；缺少合理时间字段时不伪造采样时间。TMC 行上的时间是缓存快照接收时间，界面明确标注“非现场读取”，不能据此判断芯片最后一次实际读取时刻。

## 4. 曲线、断线与会话

每张 LYX 卡片分别绘制速度、角度误差的最近五分钟历史。横轴窗口一致，纵轴按各自有效原值调整；不同卡片或两条曲线的高度不能直接拿来比较物理量大小。指针移动到曲线区域可查看最近采样点的时间和原值。

曲线直接使用后台 `history[stepper][register]`，并要求 `session_id`。页面不把不同客户端的样本拼在一起，也不把旧 Klipper 会话接到新会话曲线上。

- 失败点保留断口，不补零，不跨失败点连接。
- 两个有效点相隔超过估计正常采集间隔的两倍，也会断开。估计包含多驱动串行读取耗时、项间隔和轮间隔。
- 无有效历史时显示“近 5 分钟无有效数据”。原值恒为零时仍可画线。
- 页面连接失败或身份不匹配时隐藏该快照的读数与曲线，避免把旧缓存显示成当前可靠状态。重连成功后，以新快照恢复。
- 仅网页断线但后台继续采集时，重连可取回仍在后台保留窗口内的历史。暂停采集或后台缺失采样则留下空段，页面不会补造数据。
- 新 ready 会话使用后台的新 `session_id` 和历史；它不证明驱动芯片内的报警已经清除。

## 5. 按钮检查与报警保护

点击后先锁定页面内操作，再获取一份新快照，重新核对目标、Klipper ready 状态、后端结构版本、驱动存在与可操作状态。切换地址、页面隐藏、驱动移除或配置改变，会阻止尚未发送的命令。后台正在读取时，手动刷新不可用；一个卡片操作未结束时，其他卡片刷新及全局按钮暂时禁用，防止双击或交叉操作。

每次明确操作最多发送一次 POST，随后读取一次完整快照确认结果。POST 超时或连接中断时，“是否执行未知”表示设备可能已执行；页面不会自动重发。即使之后读到成功缓存，也不能将原来超时的请求自动解释为已成功。

三项刷新只有在目标会话未变、该轴三项结果均更新后才会确认；字段未全部更新时显示“未确认本次完整刷新”。三项均已尝试但有失败项时，也不会声称三项都读取成功。

后台上报 `shutdown_on_alarm=true` 时，页面显示“使能后报警停机”，并禁止暂停全部 LYX 监测。保护在操作前的新快照中才开启，也同样阻止暂停 POST。恢复已暂停的监测仍可使用；后端还会独立拒绝不允许的暂停，页面禁用不是唯一保护。旧后端缺少该字段时保持旧行为，不显示未经确认的保护状态。

| 每轴显示 | 解释 |
| --- | --- |
| 未使能待命 | 后台报告该轴逻辑未使能 |
| 等待使能生效 | 已逻辑使能，后台尚未确认计划使能时刻已到 |
| 已使能监测 | 后台报告当前轴已进入保护条件 |
| 等待 Klipper 就绪／使能状态未知 | 后台未就绪或缺少足够状态，不当作保护已生效 |
| 已触发报警停机 | 后台锁存了该轴的报警停机结果 |

这里的使能来自 Klipper 逻辑状态与排队使能时刻，不是物理 EN 电平测量。真正的停机由后台对同一使能周期内的新有效非零报警判定；旧缓存、跨周期结果或通信错误不当作有效报警停机。页面收到 `alarm_shutdown` 时展示其中文原因，不主动清报警、重启或恢复运动。具体保护边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 6. TARGET_CONFIG：每个安装目标单独配置

源码 `frontend/driver-monitor-config.mjs` 默认导出空配置。安装器生成运行用的 `driver-monitor-config.js`，并转换模块引用。空或畸形配置会拒绝真实页面的可信读数展示和操作；页面仍可能发出同源身份／状态 GET 以显示诊断信息，不能将它理解为完全不联网。

三类字段分别约束不同对象：

| 字段 | 用途 |
| --- | --- |
| `hostname` | 必须与同源 `/printer/info` 返回的 `hostname` 精确相等 |
| `pageOrigins` | 浏览器页面允许使用的 origin，即协议、主机、端口；不含路径、末尾 `/` 或登录信息 |
| `apiEndpoints` | 已核实属于同一目标的 Fluidd API 入口，以及该入口对应的 `printerId` |

Fluidd 地址中的 `printer` 值按其保存的 `apiUrl` 字符串计算 MD5（32 位小写十六进制）。它不是浏览器随机 ID，也不是密码或认证令牌。字符串的端口、路径或末尾斜杠变化可能改变 ID，应使用已核对的准确值，由安装器计算。

以下两份配置分别属于两台虚构机器，只能按各自目标选用，不能把两台机器合在同一份允许列表中。示例 A 假设已确认代理入口和直连入口返回同一后台身份：

```js
// 虚构机器 A；以下地址保留给文档示例。
export const TARGET_CONFIG = {
  hostname: 'printer-example-a',
  pageOrigins: ['http://192.0.2.10'],
  apiEndpoints: [
    {apiUrl: 'http://192.0.2.10', printerId: '05ebc9d6261ffaaa5afdcf73e16633af'},
    {apiUrl: 'http://192.0.2.10:7125', printerId: '4d413f32d7190d2e546ff8019f92f3ec'},
  ],
};
```

```js
// 独立的虚构机器 B；printer-b.example 可在示例网络中映射到 198.51.100.20。
export const TARGET_CONFIG = {
  hostname: 'printer-example-b',
  pageOrigins: ['https://printer-b.example'],
  apiEndpoints: [
    {apiUrl: 'https://printer-b.example', printerId: '5448da9cd0d8e5d2a7a4d5f3e9bfabf1'},
  ],
};
```

页面没有 `printer` 参数时，仍核对 origin 与 hostname。出现未知 ID、空 ID 或多个 `printer` 参数时拒绝访问。配置中的 API 入口不会自动加入页面 origin 白名单；例如示例 A 的直连端口仅作为已核对的 ID 来源，不表示允许直接在该端口展示页面。

电脑、手机、平板可访问同一个已授权 origin，并在各自浏览器完成登录；它们看到同一个后台状态。若另换 IP、域名、协议或端口，需要重新核实并配置该页面来源，不能仅复制 URL 中的 ID 就绕过身份检查。

### 同源与鉴权边界

所有请求都使用 `/printer/...` 相对路径及 `credentials: 'same-origin'`，不按 `apiEndpoints` 跨域转发。组件不读取浏览器存储中的 Fluidd token，也不自行添加令牌头；请求重定向会被拒绝。API 入口列表只用于识别页面选择，不能代替反向代理配置或登录。

安装环境必须让页面所在 origin 能访问对应 Moonraker 接口，并提供这种同源请求可使用的认证方式。如果某环境只接受 Fluidd 自己添加的 token 头，即使主页面登录成功，组件也可能收到 401／403。应核实该部署的同源代理与鉴权方式；本组件不会自动读取令牌或绕过认证。

这些检查用于避免误选目标，不是独立安全边界。hostname 和 MD5 ID 不证明服务器身份，也不替代 Moonraker 权限、网络访问控制或 HTTPS。

## 7. Fluidd 挂点与兼容范围

组件只在仪表板路由（空 hash 或 `#/`）显示。优先挂入显式的 `[data-driver-monitor-slot]` 容器；没有该容器时，尝试识别 `.app-draggable.list-group` 及其 `div.col-md-6.col-lg-6.col-12` 父列，优先选择有中文“控制台”卡片的列，否则尝试第二列。未识别到该结构时不挂载，也不会退回到页面末尾强行插入。

组件使用独立 Shadow DOM 容器和自己的样式，跟随周围卡片的颜色与字体。这是添加到仪表板列内的扩展区域，没有注册进 Fluidd 原生卡片管理或可拖拽布局；不能承诺用 Fluidd 的卡片排序、隐藏或布局持久化功能控制它。需要固定挂载位置时，由集成方提供明确容器。

历史设备定制版本曾在 Fluidd `v1.37.2-9be84b4a` 的 Edge 和内置浏览器中实测。当前通用配置分支的验证与历史部署分开记录，见 [VALIDATION.md](VALIDATION.md)。其他 Fluidd 版本、语言、主题或布局可能改变上述 DOM 结构，升级后需核对挂点。设备种类不是访问限制，但这里没有承诺所有浏览器均兼容；需要支持现代 JavaScript 模块、Shadow DOM、Fetch 等能力，并在实际客户端检查。

## 8. 离线预览

在仓库根目录使用 Python 3 启动模拟服务：

```sh
python3 -B preview/server.py --scenario multiple
```

打开 `http://127.0.0.1:18763/`，可查看两张 LYX 和两张 TMC 卡片。该服务只绑定本机 loopback，返回模拟数据，不访问打印机。模拟后台默认自动运行，关闭浏览器也会继续生成模拟缓存，直到用 `Ctrl+C` 停止本机服务。

其他启动示例：

```sh
# 用模拟数据演示两条曲线。
python3 -B preview/server.py --scenario trend --port 18764

# 正常回复场景，但先暂停模拟自动采集，便于手动刷新。
python3 -B preview/server.py --scenario ok --paused
```

可用场景为 `invalid`（默认无效回复）、`ok`、`alarm`、`trend`、`missing`、`offline`、`multiple`。页面场景控件可以切换部分场景；`multiple` 可用启动参数指定。模拟按钮只向本机模拟接口发送请求，预览结果不能作为硬件读取或真实报警停机验证。

预览 HTML 明确设置 `data-driver-monitor-preview="true"`，页面地址必须为 HTTP(S) loopback，模拟接口 hostname 必须是 `driver-monitor-demo`，才可在空默认配置下展示。不要加真实设备的 `printer` 查询参数；预览不会放行未知或重复参数。直接以 `file://` 打开 HTML 不属于受支持的预览入口。

可复现的离线检查命令：

```sh
node --test frontend/driver-monitor.test.mjs
python3 -B preview/test_server.py
```

前者覆盖配置隔离、单卡绑定、保护门禁、失败显示和曲线等逻辑；后者通过本机临时 HTTP 服务检查空配置模块、显式预览和多驱动缓存。它们不代替实际 Fluidd 挂点与浏览器显示验收。
